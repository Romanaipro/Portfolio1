## Що змінилося

Перший екран містить роль Романа, конкретну пропозицію та два переходи. Після нього — три вибрані роботи з доступом до всіх шести. Далі: задачі з прикладами → процес → автор, стек і сертифікати → пакети → оригінальні рекомендації → контакт.

Темну палітру, портрет, cyan, українську мову, ціни та прямі контакти збережено. Мій стек містить рівно: **n8n · Gemini · ChatGPT · Claude Code, Codex**. Технічні інтеграції всередині кейсів залишено за попереднім джерелом, без приписування нових інструментів.

Сторінки тепер генеруються зі спільного шаблону і є повними статичними HTML. Два невеликі скрипти додають взаємодію. Це прибирає залежність змісту від React CDN та дублювання логіки. Усі секції видимі без IntersectionObserver. Шрифт Montserrat локальний, variable WOFF2, із `font-display: optional` та preload основних підмножин.

## Перевірки й маршрути

- **Новий відвідувач:** hero → «Переглянути кейси» → три вибрані → усі шість. Пропозиція й прямий перехід доступні на телефоні.
- **Клієнт:** фільтр «Магазини й каталоги» → Urban Trend Shop → технічні деталі → «Обговорити схожу задачу». Назва переноситься у форму, фокус — у поле імені. Back повертає до відкритого кейсу; після закриття вибір фільтра збережено.
- **Рекрутер/партнер:** «Про мене» → три сертифікати з клавіатури → архітектура у кейсі → публічний GitHub. Підтверджених періодів/персональних ролей і CV бракує.
- **Зацікавлений у пакеті:** Enterprise → форма з довгою назвою → помилка валідації без POST → мок 500/невідомий 200/network збереженням полів → підтверджене прийняття й очищення. Усі повтори незмінених даних мають один ID.

`npm test`: 14 ізольованих сценаріїв/груп, зокрема 2xx із неправильним тілом або ID, 4xx/5xx, CORS/network, opaque, завислий fetch і зависле читання тіла, подвійний клік, повтор із тим самим UUID та нова заявка після успіху. Немає реальної мережі. [Збережений результат: 14/14](after/form-tests.txt).

`npm run test:browser`: Chrome 157, viewport 1440×900, 768×1024, 390×844, 320×844; усі шість кейсів, чотири фільтри, три сертифікати, prefill, історія, no-JS, мокова форма, console. Для ключових елементів перевіряються фактичні ліві/праві межі **та** внутрішній scrollWidth, а не лише ширина документа. Автоматичний axe: 0 знайдених порушень на перевіреній сторінці, 45 успішних правил.

Доступність: клавіатурні події перевірено автоматизацією реального Chrome. Ручний візуальний огляд — за скриншотами. Reflow перевірено на еквівалентних CSS-ширинах 640/320 від desktop 1280 для 200%/400%; системний UI browser zoom окремо не використовувався. Скринридери NVDA/VoiceOver, фізичний телефон і тестування з людьми не проводились. Автоматична перевірка не є повною сертифікацією доступності.

## Лабораторна швидкодія

Lighthouse **13.6.0**, Chrome **157.0.8103.51**, Windows; кожний прогін — окремий Chrome з очищеним сховищем. До: оригінальний HTML із незмінного Git-коміту, його React/Google Fonts CDN; після: локальний HTML і всі локальні залежності. Обидва варіанти — localhost, тому це порівняння коду та залежностей у тестових умовах, а не production TTFB. Перші вимірювання виконувалися на робочій машині з фоновим навантаженням; CPU/TBT та загальний бал можуть коливатися.

Mobile: 412×823 CSS px, DPR 1,75, simulated throttling, RTT 150 мс, throughput 1638,4 Kbps, CPU ×4. Три холодні прогони в однаковій конфігурації:

| Метрика | До: медіана [мін–макс] | Після: медіана [мін–макс] |
|---|---|---|
| LCP | 4,057 с [3,264–4,315] | 1,354 с [1,353–1,363] |
| CLS | 0,1068 [0,1010–0,1068] | 0 [0–0] |
| Performance | 50 [50–60] | 87 [84–89] |

Найбільший зсув до змін: `.hero-btns`, приблизно 0,101; у trace є причина `Web font loaded`. Після — список layout shifts порожній. В окремій перевірці шрифти затримані на 1,6 с: H1 та обидва CTA мають **ідентичні координати й розміри** до/після `document.fonts.ready` завдяки `font-display: optional`. За повільного шрифту браузер може залишити системний sans-serif до наступного відкриття — це свідомий компроміс стабільності.

У новій сторінці немає запитів до React CDN або Google Fonts; 37 локальних відповідей у функціональному проході — HTTP 200. CSS та шрифти лишаються залежностями першого промальовування; вони завантажуються з того самого origin. Mobile Accessibility / Best Practices / SEO — по 100 у трьох прогонах. Desktop виміряно окремо з desktop config (1350×940, DPR 1, RTT 40 мс, 10240 Kbps, CPU ×1): LCP 0,521 с, CLS 0; Performance / Accessibility / Best Practices / SEO — **100 / 100 / 100 / 100**. Точні результати — в [summary](performance/summary.json) і [повному звіті](performance/after-desktop.json).

Це не польові LCP/INP, не доведена зміна конверсії та не результати користувацького тестування. TBT не підміняє INP.

Додатково: контраст Start та Enterprise 12,07:1 normal/focus і 11,10:1 hover; основного Business Core CTA — 5,07:1 normal/focus, 7,49:1 hover. Focus-індикатор — 3 px. Axe також не знайшов порушень у станах всіх шести карток та відкритого діалогу на 1440 і 390 px. Спроба перевести фокус на фон при відкритому native dialog не виводить його з вікна.

Сім зовнішніх посилань повернули HTTP 200 на read-only HEAD-перевірці: Urban Trend, GENTLMEN CRAFT, GitHub, Instagram і три Telegram-адреси. Це підтверджує доступність URL, а не роботу оплат, ботів, CRM чи авторство зовнішнього коду. Жодних повідомлень не надсилали.

## Матеріали й рішення власника

1. **Urban Trend Shop:** 2–4 дозволені екрани каталогу, оформлення та стану замовлення в адмінці; особиста роль, команда, період, статус експлуатації. Для повернення «5×» — однакова операція, обсяг, період, метод і джерело.
2. **Мій Prom:** екрани зіставлення колонок, перевірки й схвалення; приклад прайсу без приватних даних та пояснення походження цін/артикулів; роль, період, статус.
3. **Склад:** анонімізований звіт і Excel-бланк, приклад обліку поставок; для «5 год → 5 хв» — зіставні дані й метод; роль, період, статус.
4. **GENTLMEN CRAFT / AI-менеджер / ЄДКІ:** дозволені екрани відповідно вибору товару, передачі діалогу в CRM, тесту/пояснення/прогресу; статус, період і внесок автора.
5. **Рекомендації:** першоджерело кожної цитати, дата, дозволені ім’я/посада/посилання. **Найм:** актуальний CV та конкретний public sample або погоджений спосіб приватного review.
6. **Форма:** узгодження й перевірка контракту з backend на ізольованому staging, особливо атомарної дедуплікації.
